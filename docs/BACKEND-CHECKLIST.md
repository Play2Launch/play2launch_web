# 后台接入清单 · 当前范围

本文记录已接入范围和后续设计；未标记已完成的能力不代表服务器已实现。不开放 Creator 发布功能。

## 权限边界

| 操作                       | 玩家             | 认证 KOL                   | 平台管理员       |
| -------------------------- | ---------------- | -------------------------- | ---------------- |
| 浏览已发布活动、试玩       | 可以             | 可以                       | 可以             |
| 入队、提交有效成绩         | 登录后按活动规则 | 同左                       | 不绕过计分规则   |
| 申请 KOL、查询本人状态     | 登录后可以       | 查询本人状态               | 审核并记录原因   |
| 创建战队                   | 不可以           | 按认证、截止、唯一队伍规则 | 管理权限单独审计 |
| 查看队长管理数据           | 不可以           | 仅本人创建的队伍           | 按管理角色授权   |
| 创建、修改、发布、下架活动 | 不可以           | 不可以                     | 仅管理后台       |
| 通过、驳回或撤销 KOL 认证  | 不可以           | 不可以                     | 仅管理后台       |

服务器必须逐请求校验会话、角色、资源归属及活动状态；不能通过隐藏按钮代替鉴权。认证 KOL 的 canPublishCampaign 始终为 false，不提供 Creator 申请或权限升级入口。

## 建议接入顺序

1. 身份：沿用 DashFun 账户密码/Token 与 Telegram initData 登录。前端协议和自动测试已完成，当前运行说明见 [API.md](API.md)，源码依据见 [AUTH-INTEGRATION.md](AUTH-INTEGRATION.md)；待真实浏览器/真机联调。
2. 活动读取：已实现 `GET /api/v1/campaigns` 和 `/campaigns/:slug`，Live 首页/详情已接入，带分页、加载、空数据、失败重试及404状态。本地已插入独立测试记录，草稿/下架不可见。管理员维护、游戏配置、计分截止等后续补齐。
3. KOL 认证：本人申请/查询与管理员审核分离；真实社交归属验证、审核人、原因、时间、版本和撤销日志。
4. 战队：创建、加入、按活动查询、队长数据；事务保证“用户每活动一队”和“队长每活动最多一支自建队”，创建与自动入队原子提交。
5. 游戏与计分：服务端轮次标识、结束验证、反作弊、提交幂等、服务端截止时间、最高分、去重人数与战队汇总。邀请来源与实际入队分别记录。
6. 邀请分发：服务器解析活动/队伍/邀请人，处理未知、跨活动、下架、失效链接；配置 HTTPS 与 Bot 后完成 Web/TMA 跨设备真机联调。

## 上线前必须确认

- KOL 撤销后既有战队能否继续招募；保留历史成绩，不由前端擅自删除。
- 活动下架后，已存在成员与成绩的展示、游戏入口及提交行为。
- 权限失败、队伍冲突、活动截止、请求重试的统一错误码与用户提示。
- 本地演示记录不直接迁移成真实成绩、认证或管理员权限。模拟审核、模拟招募按钮不得作为生产审核接口。
- 当前身份和活动目录/详情有 HTTP 适配。队伍、排名等页面仍为预览，真实跨账号成员关系、跨设备分享、并发一致性尚未实现；本地预览不会变成服务端入队或成绩。

## 验收重点

未登录不能写入；未认证/撤销 KOL 不能建队；非队长不能访问他人管理数据；KOL 调用活动写接口必须被拒绝；重复创建和重复提交不重复计数；邀请不自动入队；跨活动不串队；截止后的新成绩不更新榜单。
