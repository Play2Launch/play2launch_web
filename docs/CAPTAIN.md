# Captain studio · local prototype

入口：个人页 → Captain studio，或认证通过页 → Open captain studio。路径 `/captain?campaign=phood`。

模拟招募需先在个人页 Prototype settings 开启 Enable demo controls，再展开顶部演示控制台；正常队长功能不需要开启演示控制台。

## 规则

- 必须登录本地演示身份且 KOL 审核通过。未申请、待审核、驳回、撤销或 live 模式都不能通过本地操作获得建队资格。
- 每个队长每个活动最多创建一队。已经加入其他队伍的活动不可建队；不修改既有队伍、不绕过禁止换队规则。截止后不可建队。
- 队名 3–32 字符，同一活动不重名；介绍 20–300 字符。ID 由系统生成，绑定 campaignId 和 ownerId。
- 创建时自动加入自己的队伍。建队和入队不算有效参与；需要完成并保存有效轮次。原先的个人最高有效分在首次建队入队时归入该队。
- 本轮未实现改名、删除、踢人或转让队长。撤销认证后保留原队伍与成绩，禁止创建新队伍；既有队伍处置政策留待后台阶段确定。

## 联动

新队伍纳入活动队伍列表、个人 My teams、游戏队伍提示、结算、分享和排行榜。队长页显示成员、有效玩家、最高分贡献汇总和活动内排名。

分享复用原有 Web/TMA 编码，含活动 ID、队伍 ID、邀请人；TMA 链接仍需配置 Bot。没有服务器时，新队伍只存在于当前浏览器，因此链接只能在拥有同一测试队伍数据的环境解析，不能当成跨设备可用的线上邀请。未知队伍和跨活动引用不会自动加入。

顶部演示控制台提供 `Simulate invited player + valid round`：为指定的自有队伍添加一个明确标注的虚构玩家，提交 12,500 分有效轮次，复用同一计分聚合逻辑。每次点击是一个新虚构玩家，不代表真实转化或奖励；截止后不接受。没有实际发送邀请或创建外部账号。

当前真实可操作身份仍是设备本地单一演示身份。跨账号成员持久化、跨设备邀请解析、创建幂等和并发唯一约束，必须在服务器端实现；生产系统不能信任 localStorage 的身份、认证或 ownership 字段。

## 测试

组件测试覆盖认证后创建、自动入队、模拟贡献、分享参数、刷新恢复、不同活动隔离及游客/未认证拦截。纯逻辑测试覆盖重复建队、禁止换队、截止、重名、无效字段和聚合计数。无需清空已有玩家数据进行体验：若 PAPERHOOD 已有队伍，选择尚未入队的其他活动。
